# Local Resume 設計メモ

決定日：2026-10-08

## 目的

このディレクトリで、履歴書と職務経歴書をWebプレビューし、PDFとして保存する。暗号化された基本情報・会社名とパスワードをAIに渡さずに開発・運用する。暗号化しない書類内容は、ユーザーの依頼に応じてエージェントが直接編集できる。ローカル利用を前提とし、公開・ホスティングは行わない。

## 採用する構成

| 用途 | 技術 |
| --- | --- |
| 開発・ビルド | Vite + TypeScript |
| データからHTMLを描画 | lit-html（単独利用） |
| A4の改ページ・紙面プレビュー | Paged.js |
| スタイル | 通常のCSS・印刷用CSS |
| 日本語フォント | Noto Sans JPをローカル配信 |
| 暗号化・復号 | Web Crypto API |
| PDF保存 | ブラウザの印刷ダイアログ |

Reactは採用しない。lit-htmlで可変長の職歴や条件付き項目をテンプレートとして記述する。Paged.jsには復号後のDOMとローカルの印刷用CSSを渡し、ページに分割したプレビューを生成する。PDF生成サービスや外部CDNを利用しない。

## データの流れ

画面はできるだけ表示する情報を少なくし、現在の作業に必要なものだけを表示する。不要な説明文・重複した状態バッジ・常時の保存済み表示・架空の年齢や学歴例の案内・実装上のファイルパスは表示しない。「紙面で編集」「書類内容は自動保存」の説明カードは設けず、紙面上の編集操作と自動保存は維持する。保存中・未保存・入力エラー・保存失敗など、対応が必要な状態だけを表示する。ファイル選択・新規入力・再読み込み・手動保存・サンプルなどの補助操作は「その他」に折りたたむ。

会社名は職務経歴書の会社名をクリックして入力する。未入力の欄は「会社名を入力」と表示する。既存の基本情報はパスワードで解除してから編集し、初めて入力する場合は「その他」から「基本情報を新しく入力」を選ぶ。基本情報・会社名の保存欄は、新規入力・未保存の変更・会社名の移行があるときだけ表示する。

1. 起動時は `public/resume-content.json`（書類内容、通常JSON）だけを取得し、基本情報・写真・会社名を空欄にした職務経歴書のプレビューを表示する。履歴書への切り替えと書類内容の編集もパスワード不要。暗号化ファイルがない・壊れている場合でも、書類内容のプレビューを妨げない。
2. 基本情報・会社名を表示したい場合に、ユーザーがブラウザでパスワードを入力する。その送信時に初めて `public/profile.enc.json` を取得する。暗号化ファイルの手動選択にも対応する。
3. ブラウザだけで基本情報を復号し、現在編集中の書類内容と組み合わせる。解除前の本文編集や職歴の並べ替えは保持し、会社名は職歴IDで対応させる。復号の失敗時も書類内容のプレビューを残す。
4. lit-htmlで履歴書または職務経歴書を生成し、Paged.jsでA4紙面をプレビューする。職務経歴書は控えめな見出し帯・通し番号・区切り線・段落と箇条書きで構成し、所属情報と案件の説明、技術・体制の表を区別する。文章の書式化は表示だけに適用し、保存した本文は変更しない。
5. 印刷ダイアログからPDFとして保存する。書類内容だけの表示時は基本情報の必須入力を求めずに印刷できる。
6. 基本情報はブラウザ内で再暗号化し、ローカルViteサーバーの保存APIから `public/profile.enc.json` に直接保存する。未解除の表示時は暗号化保存欄を表示せず、既存の基本情報を空欄で上書きしない。学歴・職歴・資格・スキル・要約・自己PR・本人希望は、編集欄の外へフォーカスが移ると `public/resume-content.json` に通常JSONとして自動保存する。「書類内容を保存」で手動の保存・再試行もできる。
7. 「基本情報をロック」または再読み込みで基本情報・写真・会社名を外し、保存済みの書類内容のプレビューに戻る。

ユーザーの希望により暗号化の対象は氏名・ふりがな・生年月日・住所・電話・メール・任意の性別・郵便番号・別の連絡先・写真などの基本情報と会社名とする。会社名は基本情報ペイロードv2の `careerCompanies` に職歴IDごとに格納し、通常JSONにはIDと会社名を除いた職歴を保存する。職歴IDは追加時に発行し、並べ替え・削除で変化させない。未解除の表示では、会社名だけを持つ職歴のIDも自動保存時に保持し、隠れた会社名との対応を失わないようにする。IDのない従来の職歴にはブラウザの読み込み時に安定したIDを付ける。通常JSONに会社名が残る従来形式では、暗号化保存が成功するまで書類内容の保存を待ち、成功後に通常JSONから会社名を除く。基本情報ペイロードv1にも引き続き対応する。写真と切り取り位置もこの暗号化ファイルにまとめ、書類内容ファイルには含めない。編集欄と保存操作を分離し、許可した項目だけを各ファイルに出力する。従来の全項目入り暗号化ファイルはブラウザで読み込み、書類内容を別保存して移行できる。

## 暗号化

- AES-GCM、256bit鍵、128bit認証タグ。
- PBKDF2-HMAC-SHA-256、600,000回でパスワードから鍵を導出する。
- 暗号化ごとにランダムな16byteのsaltと12byteのIVを生成する。
- バージョン・暗号方式・KDF設定を追加認証データに含める。
- 保存形式は `version / algorithm / kdf / iv / ciphertext` のJSON。
- パスワードは空欄不可、1024文字以内。ユーザーの希望により12文字以上の制限と推奨文は設けない。パスワードを忘れた場合の復旧機能は設けない。
- 平文、パスワード、鍵はファイル・ログ・URL・localStorage・IndexedDBに保存しない。
- 鍵は非exportableとして生成する。JavaScriptの文字列やメモリを完全に消去できるという保証はしない。

## 最小版の範囲

- 架空のサンプル、新規JSON、書類内容の自動取得、暗号化ファイルの必要時取得・手動読み込み。
- パスワード解除、紙面の項目をクリックしてその場所で入力・反映。文章の編集はモーダルを使わず、氏名・住所などは元の場所、学歴・職歴・資格は該当行で編集する。JSONを手入力するUIは設けない。追加・削除・並べ替えも紙面で行える。単一行・複数行ともEnterで反映、Shift＋Enterで改行、Escで取り消せる。日本語入力の変換確定中は反映しない。
- 別の欄を開くときや保存・書類切り替え・PDF出力の前に、編集中の内容を検証して反映する。エラーのある入力は保持し、該当欄の近くに案内する。印刷時は入力UIを除外し、紙面をA4に再分割する。編集中のみ紙面の高さを広げて入力欄の切れを防ぐ。
- 書類内容は、編集欄（学歴・職歴・資格は行全体）からフォーカスが外れたら入力チェック後に自動保存する。同じ行の内部移動、入力エラー、日本語変換中、キャンセル時は保存しない。Enter・反映・削除・並べ替えによる変更も自動保存する。保存は背景で順に行い、古い応答で最新編集を保存済みにしない。失敗しても変更を保持し、状態表示と手動再試行を用意する。基本情報と写真は暗号化保存を継続する。
- 学歴・職歴・資格の編集は行全体をタッチ範囲にする。学歴と資格の年月は西暦の年を数字で入力し、月を選択する。3月・4月のショートカットを用意する。既存の和暦の年月も年／月に展開して表示し、年月の未選択や範囲外は入力チェックで知らせる。
- 基本情報・書類内容の項目は `null`・省略・空欄を未入力として受け付け、ブラウザ内では空文字・空配列に正規化する。暗号化した基本情報の空欄は `null` として保存する。保存時の必須入力チェックは行わず、基本情報や履歴行の入力途中でも保存できる。値がある場合は日付の実在性、連絡先の形式、文字数、学歴の年月順、職歴の開始／終了順を検証する。解除済みの書類の印刷時は氏名・ふりがな・生年月日・現住所、電話かメールと、記載した履歴行の入力不足を確認する。書類内容だけの表示では空欄を許容し、入力済みの値の形式を確認する。パスワードの入力と暗号化ファイルの形式・暗号設定・認証タグの確認は維持する。
- サンプルの学歴には、高校卒業からの架空例を用意する。実データの学歴は自動で置き換えず、学歴例を入れるボタンや年齢の説明は表示しない。
- 写真枠からJPEG・PNG・WebP（15MBまで、4,000万画素以内）を取り込める。ブラウザのCanvasで最大1600px、600,000文字以内のJPEGに変換し、撮影メタデータを引き継がない。横3：縦4の枠でドラッグと位置スライダー、拡大スライダーによる切り取り調整を行い、30mm×40mmの写真枠に表示・印刷する。変換画像と位置・拡大率を基本情報に暗号化して保存し、再調整・交換・削除に対応する。画像のURLやSVGは受け付けない。
- 学歴・職歴が1ページ目の14行に収まる場合は、2ページ目の空の続き欄は表示しない。入りきらない場合だけ「学歴・職歴（続き）」を表示する。
- 履歴書・職務経歴書の切り替え、A4のページ数表示、PDF保存。
- ユーザーが提供した職務経歴書本文・資格は、エージェントが通常JSONの `public/resume-content.json` に直接反映する。反映専用のボタンや別の下書きJSONは不要。対象外の項目と既存の職歴IDを保持する。すべての担当案件は `sharedProjects` にまとめ、所属する職歴IDを `careerIds` で紐づける。会社をまたいで継続する案件は一つの案件に複数の職歴IDを設定する。旧形式の会社別案件は本文・期間・職歴IDを維持して読み込み時に移行し、次の書類内容保存で新形式を保存する。業務改善・受賞実績は独立した本文欄に保存し、紙面でも編集できる。概算の案件期間は年単位・「年頃」を許容し、月を補わない。
- 職務経歴書はユーザー指定の `it03.docx` を項目構成の参考とする。応募職種、職務経歴要約、職務経歴、得意分野・活かせる経験、技術スキル、保有資格、自己PRの順に記載する。会社ごとに在籍期間・職種・業務概要・事業内容・資本金・従業員数・設立・売上高を持つ。案件は下の「担当案件」でのみ追加・編集し、所属する職歴（複数選択可）・期間・プロジェクト名・概要・担当フェーズ・担当業務・実績・OS・DB・NW／サーバー・クラウド・言語／ツール・役割・体制／規模／工数を記載できる。会社・案件は紙面上で編集し、案件の追加・削除・並べ替えもできる。従来の職歴本文は維持し、新項目は省略可能とする。書類内容はユーザーのブラウザで編集でき、ユーザーの依頼時にはエージェントが通常JSONを直接編集できる。
- 履歴書はユーザー指定のdodaシンプル版を参考にした白黒の罫線形式。基本はA4・2ページで、長い記載は追加ページへ送る。氏名・生年月日・任意の性別、写真枠、住所／連絡先と電話／メールの左右配置、年・月別の学歴／職歴表、2ページ目の学歴／職歴の続き・免許／資格・本人希望欄を設ける。志望動機・自己PRは職務経歴書に表示する。
- 会社買収による雇用先変更は退職・再入社と表記しない。職務要約または職務経歴の概要に変更年月と買収に伴う雇用先変更が明記され、変更前後の在籍期間に対応する場合、旧会社の退職行を省き、変更年月に「会社買収に伴い［現会社名］へ雇用先変更」と記載する。本文の担当プロダクト・案件・業務内容の継続についての説明は維持する。年月や対応する職歴が不明確な場合は推測しない。
- パスワードの確認入力、ローカルサーバー経由での暗号化JSONと書類内容の直接上書き保存。
- ロック、未保存編集の破棄確認、JSON不正・復号失敗の案内。

保存APIは既存のViteに組み込み、Node.js標準機能を使う。追加のサーバーライブラリは不要で、`@types/node` のみ開発用に追加する。保存ボタンから `public/` の決まった2ファイルに直接書き込み、移動やフォルダ選択を不要にする。ループバックからの同一オリジンJSON POSTだけを受け付け、形式・サイズ・保存する項目を検証する。一時ファイルからの置き換えで上書きし、保存失敗時は未保存の編集内容を保持する。保存データと一時ファイルをViteの監視から除外し、保存で画面が再読み込みされないようにする。プレビューサーバーでも保存を扱い、読み込みは古いdistコピーではなく現在のpublicファイルから行う。基本情報とパスワードの平文はサーバーへ送信しない。
保存先が見つからない場合は画面に配置先を表示し、「その他」→「書類内容を再読み込み」で確認できる。HTTPエラー・壊れた暗号化ファイルは画面に知らせる。従来の全項目入り暗号化ファイルを開く場合も、通常JSONの書類内容ファイルがあればその内容を優先して直接編集の結果を表示し、基本情報・写真・会社名は暗号化ファイルから引き継ぐ。書類内容ファイルがない場合は従来の内容を保持する。

## 後から追加する機能

- レイアウトの選択、日付指定、複数プロフィール。
- 必要に応じたCodex・Claude CodeのOSレベル読み取り拒否設定。実際のアプリ・バージョン・有効権限を確認し、架空のファイルで拒否を検証してから採用する。

## 個人情報の境界

基本情報と会社名の実データは暗号文のみ保存する。会社名を除く学歴・職歴などの書類内容はユーザーの選択により通常JSONで保存する。`public/` 全体、`private/`、`.env*`、PDFはGit管理対象から除外する。`public/` の両ファイルはViteビルド時に `dist/` にコピーされるため、成果物もローカルで管理する。JSONを読まない制約は実データの暗号化JSONだけに適用する。エージェントは `public/profile.enc.json` を読まず、復号もしない。暗号化していない `public/resume-content.json` は、ユーザーの依頼に応じて読み取り・直接編集してよい。変更対象以外の項目と職歴IDを保持する。画面確認・スクリーンショット・テストは架空の例だけで検証する。

`.gitignore`、`AGENTS.md`、`CLAUDE.md`はOSレベルの読み取り制限ではない。暗号化は保存データを保護するが、復号後の画面・ブラウザ操作・アプリのコード改変からの保護は別途必要。実データを表示するブラウザをAIの操作・スクリーンショット対象にしない。基本情報・会社名・パスワードを平文で扱う場合は、AI環境からアクセスできない場所に置く。通常JSONの書類内容は直接編集のため読み取りを許可する。

開発サーバーは `127.0.0.1` のみにバインドし、ブラウザコンソールのサーバー転送を無効にする。外部リソースを禁止するCSPを設定し、アプリ内のデータはHTMLとして評価せずテキストとして扱う。

## 検証

架空データだけで、暗号化・復号、日本語と改行の保持、異なるsalt・IV、誤パスワード、暗号文改ざん、異常なKDF設定、JSON形式、ブラウザ内の再読み込み・ロック、可変長の職歴、複数ページ、印刷を確認する。ブラウザ検証は専用の自動テストプロファイルで行い、実際のユーザーブラウザを接続しない。
